# DP3 predict-step optimization — talk

A quarto/revealjs presentation on DP3's predict-step optimization work,
built to be reproducible: `slides.qmd` reads from `data/*.csv` via jupyter
python cells, `data/*.csv` is generated by the scripts in `scripts/`, and
`REPRODUCTION.md` records which git branch/commit each script needs to be
run against.

This repo is independent of DP3 itself but the `scripts/` need a DP3
checkout to build against - they default to a sibling checkout (`../DP3`
next to this repo), or set `DP3_REPO=/path/to/DP3` before running one.

## Layout

- `slides.qmd` — the talk itself (quarto, revealjs, jupyter/python engine)
- `data/` — curated CSVs the slides read at render time
- `scripts/` — one script per data-generation step; see each script's header
  for the branch/commit it needs and how to reproduce its output
- `figures/` — reserved for any hand-authored assets (none yet — the four
  conceptual diagrams on slides 10-14 are generated inline in `slides.qmd`)
- `REPRODUCTION.md` — the branch/commit map, and open TODOs (notably: the
  TBB fix behind slides 8-9 is not committed anywhere yet)

## Building

Verified working with quarto 1.10.18 + a jupyter/ipykernel python3 kernel
(pandas, matplotlib, IPython, tabulate installed via pip). From this
directory:

```
quarto render slides.qmd
```

or `quarto preview slides.qmd` to iterate live. Renders to `slides.html` +
`slides_files/` (both gitignored - regenerate on demand, don't commit them).

To hand the talk to someone else or open it without quarto installed, pack
it into one self-contained file (figures, CSS and JS all inlined):

```
./scripts/pack_standalone.py          # writes dist/dp3-predict-talk.html
./scripts/pack_standalone.py out.html # or pick your own path
```

## Regenerating the data

Each script in `scripts/` is a Python script with `#SBATCH` header comments
- `sbatch` reads those regardless of the interpreter, so `sbatch
scripts/01_baseline_scaling.py /path/to/build/DP3` works directly.
`common.py` holds the shared setup (sourcing DP3's `setup_env.sh`, the
`Predict time:` log parser, etc.) - the numbered scripts import it, they
don't re-implement it. All run on `--exclusive`, 72 cores, the same node
class as the rest of this project (2x Intel Xeon Platinum 8360Y). Run them
in numeric order if starting from scratch; each writes directly into
`data/`:

| script | slide(s) | needs |
|---|---|---|
| `01_baseline_scaling.py` | 5 | a build of `figures/baseline-instrumented` |
| `02_baseline_core_cycles.py` | 5 | same build |
| `03_baseline_histogram.py` | 6 | same build |
| `04_tbb_attempt_scaling.py` | 8 | a build of the TODO TBB-fix branch (see `REPRODUCTION.md`); also needs `01` to have run first (joins against `baseline_scaling.csv`) |
| `05_memory_traffic.py` | 9 | run twice, `tbb` (TODO branch) and `final` (current HEAD) |
| `06_final_scaling.py` | 15 | current HEAD (`rebase-onto-upstream`), no worktree needed |
| `07_progression.py` | 11-14 | builds its own worktrees, no argument needed |

None of this is wired into a single "reproduce everything" entry point yet
— each script is independent and takes a pre-built `DP3` binary as its
argument (except `07`, which builds its own). See `REPRODUCTION.md` for
exact `git worktree add` commands per branch.

## What's not reproducible yet

slides 8 and 9 is sitting uncommitted in the `rebase-onto-upstream` working

is fully reproducible from a clean checkout.
